Mobile layout

Mockups at 390×780 (an iPhone-size screen). Same colors, fonts and controls as the desktop; only the layout and sizes change.

Decisions to confirm

TopicProposal
When it appliesWindow narrower than 700px: one pane, no matter how many are open. The other panes stay open and come back on a wide screen. Split and close-pane buttons are hidden.
NavigationSessions only through the drawer. Settings, Files, Project and Tasks open as a full screen with Close; the system back gesture closes them first, then the drawer.
TouchEvery button and row is at least 44px high. Hover-only controls (the project row buttons, message actions) become always visible or move into a long press or the … sheet.
TextInputs are 16px (no iOS zoom). Chat text 15px. Code blocks keep horizontal scroll.
Safe areasPadding for the notch and home bar with env(safe-area-inset-*); viewport-fit=cover.
Files paneTree and preview are two steps on a phone: the tree first, a tap opens the preview with a back arrow.
Not in this releaseSwipe gestures between sessions, push notifications, installable app (PWA) icon.
